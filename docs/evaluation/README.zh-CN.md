## 已固定的实验

第一阶段要求 100 篇不同开发案例、50 篇封存测试，按十类文章分层。主分类按主要研究目的确定，其他方法保留为标签。比较固定关键词、TF-IDF 摘要基线、冻结 V1 和冻结 V2。首轮发布门槛未通过时，最多追加一轮 100 篇开发和 50 篇全新测试。

关键词／BM25 和 TF-IDF 使用共用画像中由模型生成的关键词及 `abstract_summary`，不是作者原始关键词或摘要原文。它们属于**模型辅助的检索比较方法**。已完成的开发案例没有对两项基线做政策评审，其基线可用期刊指标保持未知。最终测试要求两名评审都检查四份匿名结果；仅排序的基线不冒充完整报告。

评估的是：**假设该研究今天作为原创、尚未投稿和发表的稿件，哪些期刊符合当前要求。**已发表终稿仅提供研究内容。不能仅因材料来源已发表而排除所有候选；真实的新颖性、文章类型、方法、伦理及现行政策要求仍须检查。终稿可能经过审稿修改，模型也可能记住公开论文，这些限制会明确披露。

生成和两次 AI 评审使用独立会话，只接收脱敏研究内容和受控来源。推荐与评审先封存，再揭晓。最终测试必须全部封存后才能揭晓任何答案。评审是同一模型的独立上下文，不冒称医学专家或不同模型的独立验证。

## 保留的协议试运行

**另有二十四篇不同文章作为协议试运行保留，不计入100篇正式开发。** 原十七篇暴露准备缺陷和含糊的发表终稿任务定义。后两篇分别使用了通知类记录或还原遮蔽后的同研究注册号。此后的五份来源输入缺陷——r23-wave10-04中的两份和此前开发案例中的三份——通过仅修改来源的修正保留为协议试运行。r24-wave10-05的两份选刊前主类标签不符属于未完成流程，不新增协议试运行数。全部原始结果和分数保留，不把排除记录改写成成功。

[协议试运行记录](protocol-trials.json)保留原始负面推荐、来源分类错误、评审分歧、中断、采用的经验和真实模型调用。修正后的回归不覆盖这些分数，也不增加案例数。[正式记录与发布门槛](results.json)单独报告新协议下的案例。

材料资格检查对整个样本库采用同一标准，与推荐结果好坏无关。共发现六篇已分配材料属于通知、摘要、社论或评论，没有完整研究：一篇已经评分的更正通知，以及五篇在选刊前或尚未使用的材料。使用同类备用文章恢复配额；其中一篇尚未开展模型评测的最终测试摘要也在评测前替换。最终测试的身份信息继续隐藏。

修正后的样本仍为 100 篇开发、50 篇最终测试，每类分别十篇和五篇。重新检查了材料类型、全文提取、许可、近重复和期刊身份配额，未发现活动样本近重复对或配额违规。一篇原标为网络研究的未选刊文章，按主要目的归入基础实验；保留身份与科学正文，网络分析和分子对接继续作为次要标签。此前许可不符和身份未核实的排除记录保持不变。替补仍须在选刊前通过全文主分类检查。

## 并行方式

十类文章各有队列，每轮每类最多一篇。案例目录与模型会话独立；整轮使用冻结的协议与 Skill，所有工作结束后集中决定规则修改。默认最多十篇同时推进、十个模型调用。每二十篇汇总进度，不改变每轮的决策节点。失败案例保留回执，不计作完成。

第一轮已终止的十类并行使用十个工作线程、最多十个模型调用。调度器测量与真实 CLI 回执的时间区间均显示峰值十。45 次 CLI 调用都完成了通信，但不代表 45 篇成功案例：两条流程未通过主分类检查，一条画像输出违反查询长度要求。七条进入诊断的流程中，一篇随后被统一材料审计判为无效，另外六篇通过中央决策。[执行失败记录](execution-failures.json)单独保留原失败，不用后续重跑结果覆盖。

此前十个小请求的通道测试，以及两篇、五篇真实并行，仍分别记录。抓取依然受主机、重定向和来源数量上限限制。[导航修复回归](execution-repairs.json)保留实际抓取次数和原分数检查，不增加案例数。一篇 Scope 词数注释不准确，但引文本身准确；原错误继续保留。

包含材料资格和画像提示词检查规则的 r21 流程已通过 242 项合成检查。两次使用已揭晓材料的真实重放均通过指定回归：每例有 20 项完整性检查、24 个周期字段审计，以及真实硬条件的反例检查。[指令修复回归](instruction-repairs.json)保留封存审计。两次重放复用来源快照，不增加新盲测案例，不替换原成绩，也不能证明准确率提高。系统综述重放保留了一次通信重连；断连尝试的用量未核到，因此可获得的终止回合 token 总数不是完整成本。

两条停止流程中的画像正确识别了主目的：`s1-public_database-019`应归生信，`s1-case_report-009`应归临床／护理。问题出在主类标签，不是网络传输或画像模型失败。有来源依据、经过独立封存检查的修正只改主类和配额元数据。原画像可在普通完成门槛下继续使用；修正本身不增加盲测案例。此次主类修正前后，原50篇最终测试的源文件、答案和遮蔽输入逐字节不变。这不撤销此前九份遮蔽输入的修正，也不声称它们从未改动。

## 证据与结果的解释

真实刊物是否被发现、Hit@3／5／10 与当前可用推荐分别报告。JCR／SCIE 未核到时保持未知。同类发表文章不能证明当前准入。身份、Scope 原句、方法政策和所有变化字段都回查捕获来源；Crossref 期刊记录只证明身份。

V1／V2 共用画像、检索候选和来源快照，比较基于相同材料的推荐判断，不等于比较自主检索能力。补充材料链接已记录；未阅读的补充内容和图像仍是证据缺口。分层开放全文便利样本不代表全部医学投稿。

最终评审程序现已让两名评审各自查看四张匿名结果卡，使用独立显示顺序并记录六组两两判断。两项基线保留原排序，不补造事实；其政策适配由独立 AI 按共用来源审查。V1／V2 胜负通过私有映射单独提取。程序已通过合成检查，真实最终案例仍未运行。共用准备成本与各比较方法新增的模型调用分开解释。每刊两篇代表论文未必包含两项基线各自最高分的支持文章，这是排序证据完整性的限制。

新协议快照在第一次推荐请求前，封存基础比较名单、共享准备材料和原始输入哈希；最终揭盲还需核验全部 50 例的这些封存记录。已有 r19 开发记录保留原有封存边界和真实成绩，不能在运行后补写准备材料清单，再冒称之前已经冻结。

报告公开分子、分母、失败、缺失、分类型结果、Wilson 区间、胜／平／负、可用候选覆盖及可获得的用量。模型写“已核验”不自动等于来源正确。缺失用量是未知，不是零；调用耗时之和包含并发评审，不等于总用时。原文、答案和完整日志不进入公开包。命中和发表先例不能换算成录用概率。

发布要求完整 100／50 记录、最终 V2 无未解决硬错误、胜数不少于负数、可用覆盖不低于 V1，以及实际行为、语言、打包和安装检查通过。这些门槛本身不证明显著提高。
