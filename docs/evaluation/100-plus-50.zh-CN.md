## 我们做了什么

**100篇开发案例、50篇最终测评都已完成。结果没有支持V2整体明显提升，稳定版发布门槛没有通过。** 因此后续版本按**实验版V2.0.0**处理，**V1.0.0继续作为稳定版**。实验版用于查看、复现和继续研究，不代表已达到稳定版质量标准；是否可下载及校验方法以[发布页](https://github.com/hujizhou35-cmd/medical-journal-selector/releases)为准。

这个项目帮助医学作者依据研究内容和当前期刊政策，比较**高分区优先、时间优先、适配优先**三条投稿路线。它要求给出来源、政策依据和未核到的事项，不提供录用概率，也不保证投稿成功。[使用示例](../examples/fictional-report.md)展示的是输出方式，不是本次测评样本。

本轮工作分成两部分：先用100篇不同的有效研究案例开发与检查流程，再冻结候选，用50篇最终案例比较V1、V2和两种固定排序方法。这里的“100+50”指案例数量，**不是150次规则修改**；很多开发决定是“不修改”，发现错误也不会自动增加一条通用规则。

关键词与TF-IDF主要回答“哪些期刊与研究内容相似”；V1/V2还要判断当前文章类型、方法政策、作者硬条件和证据。前两者只生成固定排名，不伪装成完整选刊报告。它们使用共同的模型辅助研究概念/摘要准备，因此不是完全脱离模型的纯原文基线。

真实发表期刊只是历史上一个已知出口，**命中不等于录用概率，不命中也不自动等于推荐错误**。一个相似期刊也可能因当前政策或证据不足只能暂缓。可用推荐按封存规则判断：至少一个排名候选被有效评审认可，并且该结果没有保留硬错误。不能把“发现候选”“有排名”“可用”合并计算。

## 十类别与开发流程

按**主要研究目的**决定主类别；公共数据库、网络、对接等辅助方法保留为标签，不因为出现某个方法词就换类。每类完成10篇开发和5篇最终测评：

| 主类别 | 主要目的或研究类型 | 开发完成 | 最终完成 |
|---|---|---:|---:|
| 临床/护理 | 临床或护理问题、患者结局 | 10/10 | 5/5 |
| 实验室研究 | 实验性的生物学或机制问题 | 10/10 | 5/5 |
| 公共数据库 | 基于参与者数据的二次分析 | 10/10 | 5/5 |
| 生物信息学 | 计算性的分子发现与优先级判断 | 10/10 | 5/5 |
| 预测模型 | 模型开发、验证或预测表现 | 10/10 | 5/5 |
| 网络研究 | 以网络关系或网络分析为核心 | 10/10 | 5/5 |
| 系统综述/Meta分析 | 系统检索和证据合成 | 10/10 | 5/5 |
| 其他综述 | 其他综述类型的主要研究目标 | 10/10 | 5/5 |
| 文献计量 | 出版物、引用或研究版图的计量 | 10/10 | 5/5 |
| 病例报告/系列 | 个体病例或病例系列 | 10/10 | 5/5 |

开发案例的有效闭环是：**准备并封存输入 → 生成推荐 → 两个独立上下文的盲评 → 揭晓 → 诊断 → 明确接受/不修改/拒绝决定**。有分歧时另做裁决；需要修改时先做实际回归，再冻结下一版本。完成一个模型调用，或只完成画像、推荐，不算完成一篇开发案例。

十个类别队列并行，每波每个未完成类别最多一篇。早期确实观察过十个同时模型调用；故障后的后续开发采用**最多5个同时模型调用**。队列数、工作线程数和真实同时调用数是不同口径。调度器启动后连续推进；一分钟观察器是兜底检查，不要求每个角色之间等待定时消息。完整波次结束前不读取活跃科学内容、不修改冻结输入或规则。

## V2实际增加了哪些检查

V1已要求当前来源、三条路线、未核到事项和硬条件优先。V2并不是重新发明这些规则；冻结r18相对r1把若干执行边界写得更明确：

| 变化 | 要解决的具体问题 |
|---|---|
| 方法政策的触发条件对应实际研究 | 区分研究设计、数据库来源和访问条件；不把类别标签当政策定义，不把非穷尽的验证举例改成唯一允许列表 |
| 来源记录的类型与用途分开 | 期刊登记记录可支持刊名/ISSN身份，普通论文记录不能据此证明当前文章许可、SCI收录或指标 |
| 交付文件再审计 | 在最终序列化文件中逐项核对原URL、原引文和时间，不只检查工作笔记 |
| 相对先例比较核对双方 | 判断“更强/更弱”等差异前，检查本稿和先例各自的支持材料；任一侧未知则保留未知 |
| 专业栏目许可单独核验 | 总刊允许某文章类型，不自动证明选定专业栏目允许；未核到就待核验，不额外发明实验或新颖性门槛 |
| 时间与语言更明确 | 区分初审、接收、出版、在线和收录；跟随用户语言，英文结果保留明确的Not verified（未核到） |

查看[实际Skill指令](../../skills/medical-journal-selector/SKILL.md)、[方法判断](../../skills/medical-journal-selector/references/medical-methods.md)、[来源规范](../../skills/medical-journal-selector/references/sources-and-verification.md)、[结构化证据格式](../../skills/medical-journal-selector/references/evidence-format.md)。

执行层另修复了同研究登记信息过滤、完整作者名遮蔽、浮动表格/图注提取、官方来源路径和停止/续接保护。r31修复仅处理书目先例行中平衡、无属性的`i`、`b`、`em`、`strong`格式，不放宽内容或官方政策来源要求。[限定格式回归](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/0f9ffb7adbad863643428475412252e7ca322a42/docs/evaluation/regressions/r31-inline-matcher.json)

这些软件检查和已暴露输入回归证明的是相应功能在检查范围内的行为，**没有新增普通盲测、没有修正原评分、没有证明准确率提升**。r18最终测评后的软件主体保持原冻结版本；任何后续修订都不能直接继承这50篇的验证结论。

## 最终50篇怎样比较

每篇共同准备研究概念、检索与来源窗口、预算和证据快照，事先封存固定关键词/TF-IDF排名以及比较配置。V1和V2使用同一个实际递交包；固定基线使用完整检索池。因此是受控共同准备比较，**不声称四方法看到完全相同的全部材料，也不比较四套各自独立的自动搜索**。

每篇四输出匿名、呈现顺序受控，在两个新的独立上下文中使用既有认证的**gpt-6.1-sol / xhigh**评审；有必要时使用第三个裁决上下文。两位初审在40/50篇存在字段或对决分歧，40篇实际完成第三审。所有50篇的准备、生成和评审都封存后，才揭晓最终答案；随后实际完成诊断和明确决定，不改变候选。最终50篇已经暴露，未来可作回归材料，不能再次称为新的盲测集。

检索池找到历史期刊**27/50**；实际共同递交包包含**17/50**；V1/V2各实际评估**16/50**。这些是不同阶段的覆盖，不是准确率。未命中分析按最早有证据的阻断阶段分类，不能仅凭空名单断定模型排序错误；也不能把所有历史网络失败当成最终未命中的原因。[阶段覆盖](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/0f9ffb7adbad863643428475412252e7ca322a42/docs/evaluation/final50/public_coverage_rank_summary.json)、[非命中分类](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/0f9ffb7adbad863643428475412252e7ca322a42/docs/evaluation/final50/public_nonhit_classification.json)

## 为什么稳定版门槛没通过

**严格协议门槛为GATES_NOT_PASSED。** `laboratory-017`被选入前，没有登记依据跳过更早的`laboratory-010`和`laboratory-016`储备。这项既有流程偏差不能事后补成合规。全部50篇、每类5篇、原结果与失败都保留；没有删除该篇后用49篇代替主结果。

V2仍有12/50篇带硬错误，零未解决最终V2硬错误的质量条件未满足。“胜数不少于负数”和可用覆盖略高于V1，单独通过也不代表整体门槛通过；区间重叠更不证明显著提升。V2的41个硬标记有39个篇内精确不同签名、2个重复；V1为37/37。签名不同不等于不同根因，两位评审指出同一声明也不能当两件独立错误。

还需保留以下解释限制：

- 这是按类别分层的公开可获得材料便利样本，不代表全部医学投稿；公开论文可能进入模型记忆，先前遮蔽修订和准备缺陷均已披露。
- `public_database-011`的后置诊断没有确认原主类别；仍保留原类别、原成绩和主分母，不在看到结果后换类。
- 两个独立上下文仍使用同一模型。AI盲评不是独立人类医学专家验证，完整输出风格可能暴露比较器类型。
- 50个包标注`as_of=2026-10-02`，实际来源捕获发生在10月4日UTC；来源数据日期未系统恢复，不声称历史截点验证或所有字段长期有效。[时间记录](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/0f9ffb7adbad863643428475412252e7ca322a42/docs/evaluation/final50/public_source_time_metadata.json)
- 生成器标记`verified`仅表示声明状态，不是独立正确性认证。统一的独立SCIE/JCR确认覆盖仍未知；PubMed收录不能证明SCIE。
- 可选诊断前不透明分数快照两次因窗口已过合法拒绝，没有独立历史pre/post分数字节比较证明；不补造。当前封存、源码与哈希证据保留其原证据层级。

## 实际用量与公开范围

完成50篇不代表每篇一次成功。最终流程保留**407条调用收据：393完成、5基础设施失败、9模型/契约失败**，另有1个真实terminal-only上下文，其原CLI退出码和耗时未知，不补收据。最终准备排除的3个不合格材料只消耗准备调用，不计入50篇成绩信用；相关成本仍在最终流程范围内。

公开最终包只包括允许的案例ID、数字、枚举、说明及校验清单；不公开最终文章/期刊身份、原稿、答案映射、完整日志、模型提示词、私有原因正文或凭据。[公开包哈希清单](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/0f9ffb7adbad863643428475412252e7ca322a42/docs/evaluation/final50/public-file-manifest.json)是当时生成包的不可变快照，其中发布字段不代表之后的GitHub状态；实际可用资产以发布页为准。

实验版保留冻结r18和这次结果，稳定版V1资产保持可用。没有自动追加100+50，没有把未通过门槛改成稳定发布，也没有给后续改版添加未实际发生的准确率信用。改进方向可以从检索交付、文章许可核验和最终证据序列化继续研究，但新的质量结论需要新的、未暴露评测材料。
