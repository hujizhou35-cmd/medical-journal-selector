# V2.0.0 Experimental 1

**An experimental release of the unchanged Selector r18. Stable promotion gates did not pass. V1.0.0 remains the stable release.**

**Published 5 October 2026.** [Open the prerelease](https://github.com/hujizhou35-cmd/medical-journal-selector/releases/tag/v2.0.0-experimental.1). Windows/Linux × Python 3.10/3.12 checks passed; all seven assets were downloaded anonymously and matched the release checksums. These are software and distribution checks. [Verification record](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/main/docs/releases/v2.0.0-experimental.1-verification.json) · [Actual publication workflow](https://github.com/hujizhou35-cmd/medical-journal-selector/actions/runs/37263233237)

The project completed **100 development cases and 50 final cases**. The development cases covered evolving snapshots; the final cohort tested frozen r18 against V1 and two deterministic ranking baselines. The results do not demonstrate a clear overall gain:

| Final cohort, denominator 50 | V1 | V2 |
|---|---:|---:|
| Historical outlet in the top ten | 4/50 (8%) | 1/50 (2%) |
| At least one usable recommendation without retained hard failures | 14/50 (28%) | 16/50 (32%) |
| Cases affected by retained hard failures | 21/50 | 12/50 |

Anonymous same-model AI review preferred V2 in 11 cases, tied 26, preferred V1 in 8, and remained unresolved in 5. These are different measures; a historical outlet match does not estimate acceptance probability. All 50 remain in the main results. A disclosed reserve-order deviation and remaining hard failures prevent stable promotion.

[100 + 50 process and comparison](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/main/docs/evaluation/100-plus-50.md) · [Complete final report](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/main/docs/evaluation/final50/final-report.zh-CN.md) · [Installation](https://github.com/hujizhou35-cmd/medical-journal-selector/blob/main/docs/getting-started.md)

## Choose one selector download

- **Codex:** [Skill package](https://github.com/hujizhou35-cmd/medical-journal-selector/releases/download/v2.0.0-experimental.1/medical-journal-selector-v2.0.0-experimental.1.skill). It is a ZIP archive; extract its contents directly into your project's `.agents/skills/medical-journal-selector/`.
- **Claude Code:** [Portable ZIP](https://github.com/hujizhou35-cmd/medical-journal-selector/releases/download/v2.0.0-experimental.1/medical-journal-selector-portable-v2.0.0-experimental.1.zip). Put the enclosed `medical-journal-selector` folder in `.claude/skills/`.
- **Another assistant:** [Standalone SKILL.md](https://github.com/hujizhou35-cmd/medical-journal-selector/releases/download/v2.0.0-experimental.1/SKILL.md), with the reference rules included in one file.
- **Codex Plugin:** [Plugin ZIP](https://github.com/hujizhou35-cmd/medical-journal-selector/releases/download/v2.0.0-experimental.1/medical-journal-selector-codex-plugin-v2.0.0-experimental.1.zip). Package structure is checked; native plugin import and universal host compatibility are not verified for this experimental build.

Use a separate test project to keep the experimental and stable Skill folders apart. Start a new session, then invoke the Skill with your manuscript and submission requirements. It needs your host's file access, model and current browsing; it does not include a model service, JCR subscription or acceptance guarantee. Python helpers require Python 3.10+ and are optional.

[SHA256SUMS.txt](https://github.com/hujizhou35-cmd/medical-journal-selector/releases/download/v2.0.0-experimental.1/SHA256SUMS.txt) verifies the release assets. The [software manifest](https://github.com/hujizhou35-cmd/medical-journal-selector/releases/download/v2.0.0-experimental.1/software-manifest.json) identifies the exact packaged files and normalizes text line endings to LF. No recommendation rule was changed after the final comparison. Any later revision needs new validation; these exposed final cases can serve only as regression material.
