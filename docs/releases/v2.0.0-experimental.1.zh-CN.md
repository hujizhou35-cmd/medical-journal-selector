## 100＋50是怎样完成的

**开发阶段：**10类研究，每类10篇。每篇依次完成准备、推荐、两个独立上下文评审、揭晓、诊断和明确的修改或不修改决定；接受的修改先做回归。100篇经历多个版本，不是最终V2的100次同版测试。

**最终测评：**每类5篇，共50篇。冻结V1、V2的r18版本和执行配置，与固定关键词、TF-IDF排序比较。V1/V2收到相同准备包，排序基线使用完整检索池；属于共同准备条件下的比较，不是四套独立搜索，也不声称所有方法接触完全相同的全部检索条目。

**遮蔽与隔离：**准备阶段遮蔽论文和期刊身份、作者与可直接检索原文的标识；历史期刊答案和匿名标签映射由独立答案存储保管，生成与评审上下文不接收答案映射。四份输出匿名且呈现顺序受控，由同一模型（gpt-6.1-sol，xhigh）的两个新上下文评审。40篇有初审分歧，40篇均实际完成第三上下文裁决。全部50篇的准备、输出和评审封存后统一揭晓，再诊断，不继续修改r18。

这是AI评审，不是人类专家双盲验证。无法排除模型记忆已发表论文，也无法保证输出风格完全不暴露方法。早期遮蔽修复如实披露；一项候补案例顺序偏差和剩余硬错误阻止了稳定晋级。差推荐、空结果和失败均保留在50篇分母中。已经揭晓的案例未来只能作回归材料。

## V1与V2：同一组50篇的结果

| 指标 | V1 | V2 |
|---|---:|---:|
| 历史发表期刊进入前十 | 4/50，8% | 1/50，2% |
| 至少一个可用推荐且无保留硬错误 | 14/50，28% | 16/50，32% |
| 硬错误涉及案例 | 21/50，42% | 12/50，24% |
| 保留硬错误标记数 | 37 | 41 |

V2胜11、平26、V1胜8、未决5。V2涉及硬错误的案例减少，但标记总数增加，历史期刊命中下降；不能称为整体明显提升。历史期刊命中不是录用概率。

## Token与耗时

正式100篇开发与最终流程已记录 **100,980,112输入＋6,783,345输出＝107,763,457 token**。开发31次调用、最终5条收据缺少用量，因此不是完整总成本；缓存和推理子项不重复相加。

- 较广实验记录跨度约 **3天4小时22分钟**，包含试运行、回归、检查与停顿。
- 最终9个完整波次区间合计约 **7小时8分钟**（25,696.83秒）。
- 最终流程首尾跨度约 **13小时15分钟**，包含等待、恢复和揭晓后诊断。

三种耗时范围不同，不能混称为“总耗时”，也不能把并发调用时长相加当作实际经过时间。
